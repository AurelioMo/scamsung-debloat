Safety & restore

Debloating here is reversible — but never risk-free. This page is the exact contract: what runs on your phone, what can never run, and how to undo every bit of it.

What the tool actually runs

Every phone change goes through adb shell, the same channel a power user would type by hand:

CommandWhenEffect
pm uninstall --user 0 <pkg>Removing an app (default method) Uninstalls the app for your user profile only. The APK stays in /system, untouched.
pm disable-user --user 0 <pkg>Fallback, or --disable mode Disables the app, keeping its data.
cmd package install-existing <pkg>Restoring a removed app Reinstalls the stock APK for your user.
pm enable <pkg>Restoring a disabled app Re-enables it.
settings put global/secure …Tweaks (menu option 5) Standard Android settings — original value is recorded first.
pm clear com.samsung.android.game.gosPerformance tweak only Wipes GOS statistics. This is the one irreversible side effect and is disclosed before you confirm.

There is no root, no bootloader unlock, no partition write, no flashed file, no background daemon and nothing left running on the phone afterwards.

The deny-list: what can never be removed

Critical packages are filtered out of every preset and out of manual --only requests. You cannot type your way past it:

  • Google Play Store and Play Services
  • SystemUI, Settings, Package installer, permission controller
  • One UI home launcher and Samsung keyboard
  • Phone/dialer, Contacts, SIM/telephony stack
  • IMS, VoLTE and Wi-Fi calling
  • Setup wizard and device provisioning
  • Over-the-air update components

On top of that, the tool only ever touches packages actually installed on your phone: it first asks the device what exists, then filters the preset through that list. A package Samsung renamed in a new firmware simply doesn't match — worst case is leftover bloat, never breakage.

Mandatory preview, typed confirmation

There is no flag that removes apps without showing the list first. Even with -y (which skips typing the confirmation), the full preview is still printed. Confirmation is a typed word — sim — so an accidental Enter never applies anything.

Restoring

Everything at once

Menu option 4 (Restore everything) walks the tool's own state file and runs install-existing (for removed apps) or pm enable (for disabled ones) on each. Reboot afterwards so restored apps settle back in.

A single app, by hand

adb shell cmd package install-existing com.facebook.katana   # if removed
adb shell pm enable com.samsung.android.app.sbrowser            # if disabled

Tweaks

./scamsung-debloat tweaks --reset (or menu option 5 → r) restores every setting the tool changed to its recorded original value and re-enables GOS. tweaks --status shows exactly what would be reverted.

Where the records live

~/.local/share/scamsung-debloat/ contains state.tsv (pending restores), tweaks.tsv (original values) and logs/session-*.tsv (every action with timestamps). Deleting that folder forfeits the automated restore — the apps are still recoverable via install-existing by hand.

The honest risks

  • Dependent features break. Samsung Pay plugins, watch faces and Galaxy Store content depend on Samsung services. Each preset line explains its consequence; the preview is where you catch this.
  • OTA updates may reinstall apps. Re-run the preset; nothing breaks meanwhile.
  • GOS statistics are wiped by the performance tweak (pm clear) — disclosed before confirmation, not restorable.
  • Validated against a simulator. The 73-check test suite runs against a fake adb emulating One UI 9. Your exact firmware is the final preview — which is why the preview exists.

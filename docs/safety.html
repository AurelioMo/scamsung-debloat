02 · safety & restore

Reversible —
but never risk-free.

This page is the exact contract: what runs on your phone, what can never run, and how to undo every bit of it.

What the tool actually runs

Every phone change goes through adb shell — the same channel a power user would type by hand:

CommandWhenEffect
pm uninstall --user 0Removing (default) Uninstalls for your user profile only. The APK stays in /system, untouched.
pm disable-user --user 0Fallback / --disable Disables the app, keeping its data.
cmd package install-existingRestoring removed apps Reinstalls the stock APK for your user.
pm enableRestoring disabled appsRe-enables them.
settings put global/secureTweaks (menu 5) Stock Android settings — original value recorded first.
pm clear …game.gosPerformance tweak only The one irreversible side effect — GOS statistics are wiped. Disclosed before you confirm.

No root, no bootloader unlock, no partition writes, nothing flashed, no daemon left running afterwards.

The deny-list: what can never be removed

Critical packages are filtered out of every preset and out of manual --only requests. You cannot type your way past it:

  • Google Play Store & Play Services
  • SystemUI, Settings, package installer
  • Permission controller
  • One UI home launcher
  • Samsung keyboard
  • Phone/dialer, Contacts, SIM stack
  • IMS, VoLTE, Wi-Fi calling
  • Setup wizard & provisioning
  • OTA update components

The tool also only touches packages actually installed on your phone: it asks the device what exists first, then filters the preset through that list. A package Samsung renamed in a new firmware simply doesn't match — worst case is leftover bloat, never breakage.

Mandatory preview, typed confirmation

There is no flag that removes apps without showing the list first — even -y still prints the full preview. Confirmation is a typed word, sim, so an accidental Enter never applies anything.

Restoring

Everything at once

Menu option 4 walks the tool's state file and runs install-existing (removed apps) or pm enable (disabled ones) on each. Reboot afterwards.

A single app, by hand

adb shell cmd package install-existing com.facebook.katana   # if removed
adb shell pm enable com.sec.android.app.sbrowser             # if disabled

Tweaks

./scamsung-debloat tweaks --reset restores every setting to its recorded original value and re-enables GOS. tweaks --status shows exactly what would be reverted.

Where the records live

~/.local/share/scamsung-debloat/ — state.tsv (pending restores), tweaks.tsv (original values), logs/session-*.tsv (every action). Deleting that folder forfeits automated restore; apps are still recoverable by hand via install-existing.

The honest risks

Dependent features break. Samsung Pay plugins, watch faces and Galaxy Store content depend on Samsung services. Each preset line explains its consequence; the preview is where you catch this.

OTAs may reinstall apps. Re-run the preset after a Samsung update; nothing breaks meanwhile.

GOS statistics are wiped by the performance tweak (pm clear). Disclosed before confirmation; not restorable.

Validated against a simulator. The 73-check suite runs against a fake adb emulating One UI 9 — your exact firmware is the final preview, which is why the preview exists.

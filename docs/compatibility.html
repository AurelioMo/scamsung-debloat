One UI 8/9 today. Honest after.

Any Galaxy, any computer with bash and adb — and a degradation model that fails toward leftover bloat, never toward breakage.

Phones and One UI versions

FirmwareStatus
One UI 8/9 (Android 16/17) Target. Presets come from lists community-tested on One UI 8/8.5/9 (itxjobe/samsungdebloat).
One UI 7 and older Same mechanism; preset packages that don't exist are simply skipped.
Newer / unseen versions The tool warns about the version, then proceeds — it only touches packages present on the phone, and the deny-list always applies.

Any Galaxy model speaks the same pm --user 0 — S, Z, A, M, Note, Tab. Presets describe phone apps; on tablets and foldables some lines show as "missing on device" and are skipped. Version-by-version notes: docs/oneui-compat.md (pt-BR).

Computers

HostRequirement
macOSWorks with the stock bash 3.2 — just add adb.
LinuxAny distro with bash + platform-tools.
WindowsGit for Windows (Git Bash) + platform-tools; double-click the .cmd wrapper.

Interface language follows the OS: Português, English, Español (SCAMSUNG_LANG overrides).

Known limitations

  • No storage freed. APKs stay in the read-only system partition — you gain RAM, battery and privacy, not gigabytes.
  • OTAs can reinstall apps. Re-run the preset after major updates.
  • Package renames degrade gracefully. A renamed Samsung package just stops matching; removals are never guessed.
  • Carrier firmware (US models). Carrier apps vary too much to be in the presets. Check with explain <package>, remove with apply --only <package>.
  • Galaxy AI stays by default. AI features are deliberately out of the presets — remove them individually only if you don't use them.
  • Tested on a simulator. The suite uses a fake adb; there is no physical device matrix. Report firmware-specific oddities in issues.

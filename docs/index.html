Your Galaxy ships with apps you never chose and cannot remove without root. On One UI 8 and 9, this script lists every one of them, says in a sentence what each is, and removes the ones you confirm.

  • One device read, then a single pass
  • No root, no Knox, bootloader stays locked
  • 46 package patterns it refuses to touch
  • Every removal written to state.tsv
Install in five minutes Watch a run

One read, one pass.

A preset run looks at the device once and never stops to ask again. That is the part most tools skip, and it is what keeps a run short.

The device is read once.
pm list packages runs at the start of the run. Every check after it is a local lookup, not another round trip over the cable.
Absent packages cost nothing.
A name your phone does not carry is dropped from the list before the cable is used. It is counted and skipped, never retried.
One confirmation for the whole list.
One preview, one confirmation, then adb works the list end to end. No tapping through apps one at a time.
No reboot.
Removing an app for user 0 takes effect at once, so the home screen is already clean when the script hands the phone back.

Pick how deep to go.

Three presets, each a plain text file in lists/ with one package and one explanation per line. Read it, edit it, or add your own and point the script at it. Nothing about a preset is compiled in.

Install with Heavy

Ask, refuse, undo.

Removing a package is one `pm` call, and the interesting part is not that call. It is the three things arranged around it.

Ask about one package.

explain answers for a single name: what the app is, which presets carry it, and whether the deny-list protects it. It accepts packages that are in no preset at all, which is how you settle an argument with a package ID before deciding anything.

Forty-six refusals.

The deny-list is a case block in the script, not a preference. The package manager, settings, the dialer, the keyboard, One UI Home, the Wi-Fi stack, the boot-time providers and the screen-cutout overlays all sit inside it. Naming a protected package with --only fails the same way a preset would.

The undo is a text file.

state.tsv lives in ~/.local/share/scamsung-debloat/ and holds one line per removal: the action, then the package. restore reads it and calls pm install-existing on every row. Session logs sit beside it, and the file outlives reboots, cables and firmware updates.

Before you plug the cable in.

Root, Knox, warranty?

No root. pm uninstall --user 0 removes the app from your user profile; the APK stays in the read-only system partition. The bootloader stays locked, so Knox, Play Integrity and the Samsung warranty conversation never start. Banking apps and Google Pay keep working.

Does it free storage?

Barely. That partition is read-only and the bytes stay. What changes is behaviour: background services stop starting, notifications stop arriving, and the app drawer stops being a billboard.

Does an update put them back?

Sometimes. Samsung reinstalls some of its own apps after a firmware update. Run the same preset again and the preview comes back shorter; nothing breaks in the gap.

What stops working?

Whatever depended on the removed app: watch faces and Galaxy Wearable pairing, Samsung Pay plugins, Galaxy Store updates for those apps, Bixby routines that call them. The preview names the package and explain names the dependency. restore brings it back.

Which phones does it know?

One UI 8 and 9. Older firmware usually works, but the presets are written against 8 and 9 package names; earlier builds used different IDs. The compatibility page lists what is tested and what is guesswork.

One pass, and it is done.

adb, one USB toggle, one double-click. From there a preset is one preview and one confirmation, and restore is a command that reads state.tsv line by line.

Installing an app to remove apps felt wrong.

So scamsung-debloat is a shell script instead — one file you can read in a single sitting, and you should, because it asks for your phone.

Canta and UAD are excellent, and this project reuses their risk research. But they want a background daemon or a new desktop UI. This is a menu in your own language: numbers in, preview out, typed sim, undo forever.

Every "clean Samsung" guide ends with root. This one doesn't.

A run, start to finish

Five steps. The phone doesn't change until step five.

01Install adb — once

One command on macOS, Windows or Linux. Google maintains it; the install page has all variants.

02USB debugging — once

Seven taps on Build number, one toggle, one Allow on the cable prompt. No cable? Menu option 7 pairs over Wi-Fi instead.

03Double-click

A numbered menu opens — in your language. Pick 1 for a free health check: adb, device, One UI version.

04Read the preview

Every package, what it is, what stops working without it — filtered to what is actually on your phone, minus a hard deny-list. Nothing has happened yet.

05Type sim

Only now does anything leave the phone. Ctrl+C, closing the window, or any other input — all of them cancel safely. Undo is menu option 4.

Every command it will ever run, in plain sight

The exact contract — the same pm a power user types by hand.

pm uninstall --user 0 <pkg> removes for your user profile only — /system untouched, which is exactly why undo exists
pm disable-user --user 0 <pkg> automatic fallback when uninstall fails — app disabled, data preserved
cmd package install-existing <pkg> the undo: stock APK comes straight back to your profile
settings put global/secure … tweaks only — and the original value is recorded before anything changes

Quick answers

Does it need root? Does it trip Knox?+

No and no. pm --user 0 is a stock Android feature — Knox, the bootloader and Play Integrity never notice you were here. Banking apps and Google Pay keep working.

Can I really undo everything?+

Yes. Menu option 4 reinstalls each app via install-existing, tweaks return to their recorded original values with tweaks --reset. The undo lives in a state file — it survives reboots.

Will an OTA update bring the apps back?+

Samsung sometimes reinstalls its apps after an update. Nothing breaks; run the same preset again and carry on.

Does it free up storage?+

Zero gigabytes — APKs live in a read-only partition. What you get back is RAM, background battery drain, privacy, and an app drawer that stops being a billboard.

What if an app I keep depends on a removed one?+

That feature breaks — watch faces, Samsung Pay plugins, Galaxy Store items. Every preset line warns you first, the preview shows the final list, and restore brings the dependency back.
